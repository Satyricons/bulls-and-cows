# Дизайн проекта Bulls and Cows

## 1. Структуры данных и алгоритмы

### Состояние игры

Для хранения состояния игры используется объект `GameState` (описан в `src/logic/state.ts`).
История попыток реализована как иммутабельный массив `Attempt[]`. При добавлении новой попытки создается новый массив через спред-оператор (`[...history, newAttempt]`), а не мутируется старый через `push`. Это соответствует требованиям функционального программирования.

### Алгоритм `evaluateGuess` (Быки и Коровы)

Функция реализована без использования циклов (`for`, `while`), только через методы массивов.

1. Сначала оба числа приводятся к нижнему регистру и разбиваются на массивы символов.
2. Вычисляются **быки**: через метод `filter` мы находим позиции, где символы совпадают, и берем длину этого массива.
3. Для вычисления **коров** мы отбрасываем символы, которые уже стали быками. Оставшиеся символы секрета и попытки сравниваются с помощью `reduce`. Если символ из попытки есть в остатке секрета, мы увеличиваем счетчик коров и удаляем этот символ из остатка (чтобы одинаковые цифры не посчитались дважды).

### Алгоритм `countPossibleSecrets`

Количество возможных секретов — это количество перестановок без повторений, которое вычисляется по формуле `P(B, L) = B! / (B - L)!`.
Алгоритм реализован **рекурсивно**: `countPossibleSecrets(length, base) = base * countPossibleSecrets(length - 1, base - 1)`. Базовый случай: если `length === 0`, возвращается `1`.
Для оптимизации применена **мемоизация**: результаты сохраняются в `Map` по ключу `${length}:${base}`. При повторном вызове с теми же аргументами функция мгновенно возвращает результат из кэша.

## 2. Сложность алгоритмов (Big O)

- **`generateSecret` — O(L²)**, где L — длина секрета. На каждом шаге (всего L шагов) происходит выборка случайного элемента из массива доступных символов и его удаление через `splice`. В худшем случае `splice` занимает O(L). Поскольку база (алфавит) ограничена 16 символами, это можно считать константой, но относительно длины — O(L²).
- **`evaluateGuess` — O(L²)**. Метод `filter` для поиска быков занимает O(L). Затем `reduce` для поиска коров внутри использует `indexOf` и `splice`, которые в худшем случае занимают O(L). Итого O(L * L) = O(L²).
- **`isValidGuess` — O(L)**. Проверка длины занимает O(1). Метод `every` проходит по строке O(L). Создание `Set` для проверки уникальности также занимает O(L).
- **`countPossibleSecrets` — O(L)**. Глубина рекурсии равна L, на каждом шаге выполняется O(1) операций. Благодаря мемоизации, повторные вызовы с теми же аргументами занимают O(1).

## 3. Принципы чистого кода

- **Чистые функции (Pure Functions)**: Вся игровая логика в `src/logic/` не зависит от DOM и глобального состояния. Например, `evaluateGuess` и `generateSecret` возвращают результат исключительно на основе переданных аргументов.
- **Внедрение зависимостей (Dependency Injection)**: Функция `generateSecret` принимает `random: () => number` третьим аргументом. Это позволяет в тестах передавать предсказуемую функцию вместо `Math.random()`, делая тесты детерминированными.
- **Каррирование (Currying)**: Функция `createDigitValidator` (в `src/logic/createDigitValidator.ts`) принимает `base` и возвращает функцию-предикат. Это позволяет переиспользовать валидатор в двух местах: для проверки всей попытки в `isValidGuess` и для фильтрации каждого вводимого символа в UI (`src/ui/game.ts`).
- **Иммутабельность**: Обновление истории в `src/logic/state.ts` (функция `addToHistory`) и сортировка рекордов в `src/logic/leaderboard.ts` (функция `sortRecords`) не мутируют входящие массивы, а возвращают новые.
- **DRY (Don't Repeat Yourself)**: Создание DOM-элементов вынесено в единую функцию высшего порядка `createElement` в `src/ui/elements.ts`, что исключает дублирование кода при создании интерфейса.
